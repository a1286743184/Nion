### 1.2 原设计意图判定（决定我们保留什么）

原范式是「文档列表 + 容器定类型」：笔记 = 位于 notebook 型清单中的 task 行，渲染、搜索、统计全部由清单类型推导。该范式被两个演进打破：主列表换成共享树形组件（子笔记合法可见）+ AI 工具层跨通道操作（task 通道的 parent 用在笔记上）。

**升级方向遵循滴答清单模型**：任务与笔记是同一种实体的两种 `kind`，可互转，区别仅是能否勾选完成。原范式里自洽的部分（容器决定默认值、文档式搜索语义）保留；被打破的部分（实体无类型发言权、读写通道分叉）修正。

### 1.3 实测问题登记（已定位，修法归入各模块）

- AI 称「任务应该是平铺的」→ 实为模型撞上 F4 假失败后自圆其说；companion 全部代码无「平铺」约束。
- 笔记空态文案「暂无任务/添加第一个任务」：`TaskScreen.kt:1363-1368` 无 isNotebook 分支。
- 笔记清单顶部统计「N项待办 · N项已完成」：`TaskScreen.kt:629` 无条件渲染。
- 笔记编辑器顶距过近：`NotebookEditor.kt:131-135` 故意只取状态栏高度 60%。
- 关联任务 chip 一触即删：`NotebookEditor.kt:338` onClick 直调 onUnlinkTask。
- 子任务分组可设置但不生效（筛选只按根任务折叠树）→ 交互层误导，处理见 7.4。

## 2. 设计原则（后续所有设计的裁决准绳）

1. **单实体原则**：task/note 是同一实体（tasks 表）的两种 kind；类型是实体的属性，清单类型只决定新建默认值与视图语境，不再决定渲染。
2. **点任务原则**：不引入「结束时间」。时间占用由 `reminder`（起点）+ `expected_minutes`（时长）派生；排期是派生视图，不是核心模型。任何新增字段不得与既有字段形成隐式耦合。
3. **工具诚实性原则**：工具返回必须与数据真相一致。写入成功不得报错；目标状态已达成视为成功（幂等）；部分成功必须如实报告已应用部分。
4. **通道统一原则**：同一数据只有一个权威读写通道。note/task 两个透镜共享同一底层实现，返回结构统一，元素携带 `kind`。
5. **通知兜底原则**：任何提醒的增强展示形态（浮窗等）必须以系统通知为兜底，任何代码路径不得在展示增强时撤除兜底。
6. **复用优先**：能用既有字段/表/接口表达的不新增（focus_seconds、focus_sessions、linked_task_ids、resolveTaskOwnership 等全部复用）。
7. **内容先于装饰**：首屏先回答「现在有什么、下一步做什么」。单屏一个主操作；类型、时间、进度以文字/图形表达，不新增用于区分业务类型的颜色。
8. **连续而非炫技**：从卡片进入的内容从原位置展开，从侧栏进入的内容保持左右方向，返回时沿来路恢复。动画不延迟可用操作，不阻塞数据库读写。
9. **显式确认，结果诚实**：AI 排期先预览、后由本地控件确认；部分成功、未排入、保存失败都直接呈现，不用「已全部完成」掩盖。
10. **安静且可访问**：通知与浮窗不重复抢夺注意力；非紧急状态不使用红色、震动或全屏打断。状态不能只靠颜色传达，触摸目标至少 48dp，动态内容兼容系统减少动画设置。

## 3. 数据层设计（core / SQLite）

### 3.1 Schema 变更

```sql
ALTER TABLE tasks ADD COLUMN kind TEXT NOT NULL DEFAULT 'task';      -- 'task' | 'note'
ALTER TABLE tasks ADD COLUMN expected_minutes INTEGER;               -- NULL = 未规划时长
```

- 迁移沿用现有 lenient ALTER 链模式（`nion_core.rs:133-148`）。
- 当前为测试期（无真实用户数据）：迁移后允许一次性 `UPDATE tasks SET kind='note' WHERE category_id IN (SELECT id FROM checklists WHERE checklist_type='notebook')` 刷存量。正式发布前须移除此一次性刷写、冻结迁移语义并升 schema 版本。
- `TaskData` 增加 `kind: String`、`expected_minutes: Option<i64>`（uniffi Record 变更 → 重新生成 Kotlin 绑定、重编两个 ABI 的 `.so`，流程按 `build-android.sh`）。

### 3.2 实体类型语义

- `kind='task'`：可勾选，status/completed_at 语义完整。
- `kind='note'`：无勾选语义；status 字段物理保留但 UI 与工具层不赋予语义。
- **互转** = `update(kind=...)`：
  - task→note：completed_at 保留（转回 task 时恢复已完成状态显示）；
  - note→task：status 从 `todo` 起；
  - focus_seconds / focus_sessions / linked_task_ids / 附件全部跟随实体保留（属于实体，不属于类型）。
- **创建时 kind 来源**：AI 通道 `create(entity_type=note)` → kind='note'，`entity_type=task` → kind='task'；UI 在笔记型清单新建 → 默认 'note'，任务型清单 → 默认 'task'；创建表单顶部用「任务 / 笔记」双段选择器显式覆盖，智能清单默认 'task'，布局与转换规则见 7.6（U-01）。
- **渲染决策权迁移**：SharedTaskCard / SharedTaskList 以实体 `kind` 决定图标/勾选框/描述渲染；`isNotebook` 参数退役为「新建默认值提示」，不再驱动已有实体渲染（见 7.1）。

### 3.3 组合更新事务化（消灭假失败的根）

现状：归属变更（parent/group/checklist）走独立接口各自自动提交，字段更新走 `update_task`，组合操作无事务，且后者在仅归属变更时报错（F4）。

新增 Rust 接口（一次锁、一个事务内完成全部变更）：

```rust
/// 组合更新：字段 + 归属一次提交。
/// FFI 约束：UniFFI 不支持嵌套 Option，"未提供 / 置空" 用显式标志位区分。
pub fn update_task_full(
    &self,
    id: String,
    name: Option<String>,
    description: Option<String>,
    priority: Option<String>,
    status: Option<String>,
    kind: Option<String>,              // "task" | "note"
    expected_minutes: Option<i64>,
    category_id: Option<String>,
    set_group: bool, group_id: Option<String>,   // set_group=true 时应用（group_id 可为 None=清除）
    set_parent: bool, parent_id: Option<String>, // set_parent=true 时应用（可为 None=提升为根）
    reminder: Option<String>,
    recurrence_rule: Option<String>,
    recurrence_reminder_time: Option<String>,
) -> Result<TaskData, NionError>
```

事务内步骤：环校验（沿 parent 链上溯，拒绝 A→B→A，含自环）→ 写入全部字段 → 级联子孙 category/group（复用 `cascade_to_descendants`）→ 返回完整实体。

语义修正：
- `update_task` 保留给单字段路径，其 `No fields to update` 守卫保留（防空调用），但工具层不得再产生「归属接口 + 空 updateTask」组合。
- Kotlin 工具层 `executeUpdateTask` 改为：先解析校验全部参数 → 一次调用 `update_task_full`。原 `updateTaskParent`/`updateTaskGroup` 独立调用点保留给 UI 现有路径（`TaskViewModel.kt:690、707`），后续可逐步收敛。

### 3.4 查询接口

```rust
/// query=None 且 checklist_id 给定 → 枚举该清单全部笔记。
/// include_children=false 保持文档式搜索（只搜根）；true 时包含子笔记。
/// UI 调用方一律 false（保持现状语义）；AI 调用方 true（需要完整视图）。
pub fn search_notes(

```

- `get_tasks` / `get_tasks_by_category` 系列自动携带 kind（TaskData 字段）。
- 收集箱（INBOX）聚合语义已核实：当前 Kotlin 调用 `loadTasksWithSubtasks(null, null)`，Rust 对应 `category_id IS NULL` 的顶层实体，子项随根递归加载；不是「无分组的任务」。B5 抽象时保持该口径，kind=note 也遵循同一规则。证据：`TaskViewModel.kt:327-335`、`nion_core.rs:293-321`。

## 4. AI 工具层契约（UnifiedTools）

### 4.1 诚实性规范（所有工具强制）

1. 先校验后执行：全部参数解析失败时，零写入并返回明确错误。
2. 幂等：目标状态已达成 → 返回 success + 当前实体（不产生额外副作用）。
3. 字段构建统一：id / ids / name / names 四条定位路径必须共享同一个「参数 → 变更集」构建函数，消灭分支行为分叉（F4 的结构性根源）。建议实现形态：`TaskChangeSet.fromParams(params, core): TaskChangeSet?`，各路径只负责把定位符解析成 id 列表，变更集构建与执行完全共用。
4. 返回值与数据一致：批量操作逐项如实报告；不存在「报错但已写入」。

### 4.2 note/task 通道统一

- `create`：note 通道支持 parent（复用 `resolveTaskOwnership`），并按 entity_type 写入 kind。batch items 同步支持。
- `query`：
  - note 通道 name 变为可选；无 name 时按 checklist（可选）枚举；
  - name 有值时全文搜索（include_children=true）；
  - task 通道不变，返回元素自然携带 kind。
- 返回结构统一：实体查询一律 `{ "items": [...], "count": n }`，元素含 `kind`。旧顶层 key（tasks/notes）直接废弃——唯一消费方是 LLM 与 CompanionViewModel，实现时 grep `optJSONArray("notes")` 类解析点确认无遗漏。
- `update`：note 等同 task（现有 effectiveType 映射保留），走 3.3 的 `update_task_full`；`kind` 成为可更新字段（互转入口）。
- `delete`：不变（note 已等同 task）。
- 工具 schema 描述统一改写为互转语义：「笔记与任务是同一种实体，可互转，区别是能否勾选完成；笔记本内可存在任务，任务清单内可存在笔记」。消除 AI 的类型心智偏差。

### 4.3 新增 schedule 工具（排期）

**输入契约**：

```json
{
  "tasks": [ { "name" 或 "id", "expected_minutes"? } ],
  "fragmented": [ { "name", "minutes_per_day", "chunk_minutes"? } ],
  "time_windows": [ { "start": "09:00", "end": "11:00" } ],
  "start_date": "YYYY-MM-DD",
  "confirm": false
}
```

- `time_windows` 缺省时读取设置 `daily_time_windows`（见 4.3.1）。
- 各任务 expected_minutes 缺省时：查任务字段；仍缺失 → 该任务进 `unplaced` 并说明原因（诚实性：不猜时长）。
- 已占用块自动推导：现有任务中 `reminder + expected_minutes` 落在窗口内的区间视为已占用；无 reminder 的任务不参与。
- `fragmented` 为可碎片化任务（如「每日行测刷题 1 小时，可拆 30 分钟块」），均匀插入空隙。

**输出契约**：

```json
{
  "assignments": [ { "task": "...", "date": "...", "start": "09:00", "end": "11:30" } ],
  "earliest_completion": "YYYY-MM-DD",
  "unplaced": [ { "task": "...", "reason": "缺少 expected_minutes" } ],
  "confirmed": false
}
```

**算法与边界**：按优先级 + 建议截止排序的贪心装窗；不做约束求解器、不做跨天拆分（后期可选）、排期上限 90 天。**排期结果是建议**：`confirm=true` 才批量回写各任务的 reminder（一次性 update 循环，逐项如实报告）。聊天中展示按天分组的预览卡片、未排入原因与「应用排期」按钮，完整状态机见 7.10（U-02）。

**4.3.1 设置项**：`daily_time_windows`（JSON：`[{"start":"09:00","end":"11:00"},...]`），V1 每天相同；V2 可按星期差异化。设置入口、时间编辑与校验规则见 7.11（U-03）。

**4.3.2 预览数据契约**：聊天卡片不能消费模型重新排版的 Markdown 表格，须由工具结果映射为本地 `ScheduleProposalUiModel`。该模型携带 `proposalId`、`createdAtEpochMs`、`assignments`、`unplaced`、执行状态与逐项错误；`assignments` 除日期和起止时间外必须携带稳定的任务 `id`，不能靠同名标题回写。每项另带 `originalReminder` 供过期校验；B6 应在 4.3 的 assignments 输出中同步补充 `id` 与 `originalReminder`，`title` 仅用于显示。`confirmed=false` 只代表服务端/工具层的写入意图，不自动等价于 UI 已确认。

- **持久化与过期**：`ChatMessage` 增加可空结构化 payload（`type="schedule_proposal"` 与对应 JSON），随现有 `chat_conversations.messages` 一并序列化，不新增第二套会话数据库。应用重启后仍可查看；写入时读取最新实体，过期预览不得盲目覆盖用户后来手动修改的时间。工具需为每项提供 `originalReminder`，UI/确认器在确认前将其与当前 reminder 比对；发生变化则该条标记「需重新排期」，不纳入本次写入。confirming 期间的 `appliedIds` / `failedIds` 与逐项错误随卡片持久化；异常重启恢复为 partial 或待校验的 preview，重试前先读当前值并识别已经写入的项，不自动重放整批写操作。
- **确认语义**：预览不写入；点击「应用排期」直接触发本地 `schedule(confirm=true)` 调用，不要求模型再次生成结果。请求中的分配项来自已持久化的 proposalId，不是让模型自由复述。若 4.3 的 `confirm=true` 实际接口仍需补 `proposalId + assignments` 输入，应在 B6 同步补齐，前端不自造另一套写库路径。
- **生命周期**：`idle → preview → confirming → applied | partial | failed`；失败或部分成功保留原卡片与重试入口。确认按钮在 confirming 中禁用并显示行内进度，不能重复提交。关闭侧栏不取消已开始的确认，重新打开恢复到同一状态。
- **跳转与返回**：点击分配项/「查看日程」关闭右侧伙伴面板并切到日程页对应日期；返回时恢复此前的伙伴会话与滚动位置。排期卡片保留在聊天记录，已应用卡片只读，防止旧建议被再次应用。

### 4.4 记忆触发

机制链路不动（F9 全部保留）。补系统提示词行为规则，注入位置为 `CompanionViewModel.kt:2368+` 的稳定前缀构建处。规则框架（措辞属 prompt 设计，后续迭代）：

> 当用户在对话中透露稳定偏好、日程习惯、身份事实或明确要求记住某事时，先调用 memory 工具记录，再继续回复；同类记忆优先 update 而非新增。

可选强化：每轮回复后的轻量检查点（判分是否应记录），成本高则不做，先观察提示词规则的效果。

## 5. 智能清单框架

- 定义注册表替代硬编码特判（F10）：

```kotlin
data class SmartListDef(
    val id: String,        // "smart_today" / "smart_tomorrow" / "smart_week" / "smart_7d" / "smart_30d" / "inbox"
    val label: String,     // 今天 / 明天 / 本周 / 最近7天 / 最近30天 / 收集箱
    val filter: (TaskData) -> Boolean,   // 统一聚合函数
)
```

- 内置全集：今天、明天、本周、最近 7 天、最近 30 天、收集箱；设置页勾选启用集合（存 settings 表）。
- `TaskViewModel` 的 TODAY_ID / INBOX_ID 特判（106、142-151、291+）全部迁移为注册表遍历；「今天」「收集箱」保持默认启用，保证现有体验不变。
- 智能清单不可删除、不可重命名；顺序固定在自建清单之前。侧栏采用扁平「智能清单 / 我的清单」两层信息分组，设置项与启停规则见 7.12（U-04）。
- **聚合口径定稿**：今天/明天/本周/最近 N 天一律按 `reminder` 的本地日历日期过滤，包含已完成实例并沿用现有列表的待办/已完成分区；无 reminder 的实体只进其真实清单或收集箱，不因创建日期进入时间视图。「本周」为本地时区周一至周日，含今天；「最近 7 天 / 30 天」为含今天在内的连续 7 / 30 个自然日，不是未来 N 天。`expected_minutes` 只决定时间占用，不改变是否入选。重复任务按既有实例化逻辑先展开再过滤。

## 7. 前端设计定稿

### 7.1 体验方向与现有结构

**设计关键词：温暖、留白、轻盈、连续。** 不另起一套视觉语言，不增加底部导航，不把任务、笔记、日程拆成相互割裂的工具。延续当前暖米色背景、白色内容面、单主色强调、圆角卡片、左侧清单 / 右侧伙伴的双面板和五个底部入口。此次升级主要减少模式困惑与操作断点，而非增加页面数量。

- **保留的骨架**：`tasks / schedule / pomodoro / music / settings` 路由不变；左侧清单宽 260dp、右侧伙伴宽 320dp；任务和笔记仍由同一主列表承载，伙伴可以在任意页面呼出。
- **内容层级**：页面标题与当前清单位置 → 当前列表/日期 → 主操作；高级字段收进详情或次级面板。主界面不常驻类型筛选器、批量工具栏或统计图表。
- **导航原则**：实体 `kind` 决定打开任务详情还是笔记编辑器，不再由所在清单决定。跨清单、跨日程、跨聊天打开同一实体时，都复用同一详情组件和编辑器。
- **响应式边界**：以现有手机布局为基线。侧栏仍覆盖并缩放主内容，不在窄屏并排挤压内容；详情最大高度为可用高度的 85%，宽屏时内容最大宽度 560dp 并居中，列表不无限拉宽。所有表单处理 statusBars、navigationBars 和 IME insets。

### 7.2 视觉语言与组件约束

直接复用 `NionTypography`、`NionShapes`、`MaterialTheme.colorScheme`、`NionAlpha`。新增业务样式先进入 `ui/theme`，禁止在页面中散落固定颜色和透明度。任务/笔记不使用两套主题色；主色表示主操作与当前选中，secondary 表示信息与入口，error 只表示错误、逾期与不可逆操作。

| 项目 | 定稿规格 | 使用位置 |
|---|---|---|
| 页面留白 | 水平 16dp；区块间距 16dp；组间距 24dp | 主列表、设置、详情 |
| 卡片 | 普通内容 `shapes.medium` 16dp；浮层 `shapes.large` 24dp | 列表、详情、排期卡 |
| 输入控件 | 14dp 圆角，聚焦只用主题色细边框，不叠加多层粗边框 | 新建、重命名、时间窗 |
| 芯片 | 8dp 圆角或全圆角；高度至少 32dp，整体点击区至少 48dp | 类型、关联、筛选 |
| 图标 | 常态 18～20dp，辅助元信息 14～16dp；必须有 contentDescription 或邻近文字 | 全模块 |
| 点击目标 | 视觉图标可小，实际触摸区至少 48×48dp | 返回、移除关联、勾选、菜单 |
| 分隔 | 优先留白；确需分隔用 `outlineVariant` 的弱强调，不加粗重卡片阴影 | 分组、关联列表 |
| 文本 | 页面标题 `headlineSmall`，卡片标题 `bodyLarge`，区块标题 `labelLarge`，元信息 `bodySmall` | 全模块 |
| 数字与日期 | 时间范围、计数使用等宽数字特性；同一卡片统一 HH:mm 与中文日期格式 | 排期、专注、提醒 |

**共享组件边界**：`SharedTaskCard` 负责实体外观，`SharedTaskList` 负责层级、分区和手势，`NionBottomSheet` 负责需要选择/确认的模态操作。详情、笔记编辑器、聊天排期卡是三个独立业务组件，不把它们塞回已经很大的 `TaskScreen` / `CompanionSidebar`。

### 7.3 按实体渲染：任务与笔记混排（U-01 关联）

`TaskCardModel`、`TaskItem` 和日程映射模型统一增加 `kind: String` 与 `expectedMinutes: Int?`。`SharedTaskCard` / `SharedTaskList` / 统计与空态组件以实体 kind 决定外观；`isNotebookView` 只负责新建默认值、所在清单文案和「以笔记方式创建」的快捷语义，不能驱动已有实体渲染。

| 实体外观 | 任务 `kind=task` | 笔记 `kind=note` |
|---|---|---|
| 左侧标识 | 24dp 圆形勾选区，颜色继续表达优先级 | `FileText` 20dp 中性图标，不可勾选、无空 checkbox |
| 标题 | 单行省略，完成后弱化并保留划线动画 | 单行省略，永不显示完成态划线 |
| 摘要 | 描述单行；有安排时显示提醒/预计时长 | `stripMarkdown` 后显示两行以内摘要，优先内容而非元信息 |
| 点击 | 打开任务详情浮层 | 打开全屏 Markdown 编辑器 |
| 完成动画 | 保留现有对勾、划线与位移顺序 | 不触发，不进入「已完成」分区 |
| 日程 | 有 reminder 时参与；显示预计占用 | 有 reminder 时也可显示，但无勾选；点击进编辑器 |

- 卡片高度随内容自然增长，笔记最多比任务多一行摘要；不为对齐强行给所有卡片加等高空白。
- 笔记转任务时，在同一个稳定 item key 上把笔记图标 crossfade 为勾选圈，再更新列表分区；任务转笔记时反向处理，不重挂整棵列表。
- 父任务和子笔记可以共存。层级由 parent 决定、完成能力由 kind 决定；父级为笔记时子项可以创建任务或笔记，父级为任务时亦然，术语统一用「子项」。
- 勾选仅作用于 task；批量操作按 kind 过滤，不对 note 伪造完成状态。

### 7.4 列表分区、统计与完整文案（U-10）

列表不因为类型混排增加密集分区。主分区包含所有笔记与未完成任务：纯笔记时命名「笔记」，纯任务时命名「待办」，混合时命名「进行中」；下方「已完成」区只含 task，没有已完成任务则不渲染。父项及其子项仍按现有树形规则组织，不按 kind 拆散重排。

**统计口径**：顶部副标题统计当前清单/筛选结果中的全部子孙实体，不按正文是否为空过滤；进行中数包含未完成任务和全部笔记，已完成数只包含任务。笔记计数按实际 kind，而不是按 `checklist_type`。计数标签在混合语境始终带单位，避免「3 项」无法判断是任务还是笔记。

| 场景 | 顶部副标题 | 空态标题 | 空态辅助文案 / 主操作 |
|---|---|---|---|
| 任务型清单，只有任务 | `3 项待办 · 1 项已完成`；全部完成时 `全部完成，共 4 项` | `还没有任务` | `点击 + 添加第一个任务` |
| 笔记型清单，只有笔记 | `3 条笔记`；清单为空显示 `暂无笔记` | `还没有笔记` | `点击 + 写下第一条笔记` |
| 任意清单，任务与笔记混排 | `2 项待办 · 3 条笔记 · 1 项已完成`，省略为 0 的部分 | `从一件小事开始` | `点击 + 新建任务或笔记` |
| 今天 | `今天还有 3 项待办`；无待办但有笔记 `今天有 2 条笔记` | `今天没有安排` | `留一点空白，或点击 + 添加任务` |
| 明天 / 本周 / 最近 7 天 / 最近 30 天 | `这段时间有 3 项待办 · 1 条笔记` | `这段时间没有安排` | `可以在其他日期安排任务` |
| 收集箱 | `2 项待整理 · 1 条笔记` | `收集箱是空的` | `点击 + 记录一个想法` |
| 笔记搜索无结果 | 保留当前清单统计，不覆盖 | `没有找到相关笔记` | `换个关键词试试`；提供「清除搜索」 |
| 分组筛选无结果 | 顶部统计仍显示当前筛选结果 | `这个分组还没有内容` | `点击 + 添加任务或笔记` |

- 空态不放大面积插画；使用细线 `FilePlus2` / `CircleCheck` 24dp 图标、标题、辅助文案三行结构，垂直居中并保留底部 FAB 的安全空间。
- 加载中已有内容时保留原内容，不闪空白或全屏骨架；首次加载才显示低对比度列表骨架。空列表必须等首次加载完成后再展示空态。
- 智能清单计数按同一口径展示，未完成数放右侧，完成数不抢视觉焦点。通知权限、保存失败等全局错误不能被空态掩盖。

### 7.5 任务详情浮层：固定骨架 + 可滚动内容（U-07）

保留从任务卡片 morph 展开的详情浮层与 DETAIL / ADD_SUBTASK / REMINDER / RECURRENCE 面板，不增加第五种并列 Tab。DETAIL 重排为「固定标题与操作、单一滚动正文、固定专注与底部工具」三段，避免新增两区块后备注框被压扁。

1. **固定头部**：返回/关闭、可编辑标题、实体 kind 的小图标与「任务」标签。头部高度不随内容长度变化。
2. **滚动正文**：提醒与重复入口 → 预计时长 → 备注与附件 → 子项 → 关联笔记。正文使用一个滚动容器，不嵌套多个独立滚动的 Column。
3. **固定底部**：专注摘要/播放按钮与「添加子项」「更多」；删除从首屏底部工具移到「更多」菜单，降低误触。专注区仅 task 显示；note 若打开任务详情只能来自过渡态，须立刻切换为编辑器而不是保留任务操作。

**子项区**

- 标题行 `子项` + 数量（全部子孙总数），右侧文字按钮「添加」。数量指实体数，不将 task/note 混称为子任务。
- 使用紧凑树形行：图标（checkbox 或 FileText）+ 标题 + 可选时间；每级缩进 16dp，最大视觉缩进 3 级，更深层级保持缩进并在标题前显示父级名称辅助定位。
- 默认显示直接子项及已展开的后代，深层内容超过 5 行时显示「展开全部 N 项」；展开后在同一滚动正文内显示，不弹第二个浮层。树线使用 1dp `outlineVariant`，不得穿过文字和点击区域。
- 点击子项：**同一个详情浮层更新到新实体**，用 180ms 淡入 + 12dp 水平位移，容器不关闭再打开。保留详情返回栈，头部出现返回箭头；系统返回先回父级，栈空才关闭浮层。kind=note 的子项转场到笔记编辑器，返回时恢复父任务详情。
- 无子项不渲染空框；只保留正文末尾的轻量入口 `添加子项`。有子项但加载失败时在本区显示 `子项暂时无法加载` + `重试`，不清空已加载的备注与关联。

**关联笔记区**

- 标题行 `关联笔记` + 数量，右侧「添加」复用现有双向 `link_task_and_note`。每条为 `FileText + 标题 + ChevronRight`，标题最多两行，整行可点击；不塞入正文摘要。
- 无关联时显示一行 `把相关资料放到手边` + `关联笔记`，不展示占位卡片。关联选择器只列 kind=note，支持按标题搜索、已关联状态勾选；保存后双向立即可见。
- 点击笔记，从该关联行 sharedBounds 进入全屏编辑器；记录来源为「任务详情 + 原列表滚动位置」。关闭编辑器返回原任务详情，再次关闭才回原列表，不能直接跳回清单首页。
- 关联行的「更多」内提供「取消关联」，此操作只解除关系、不删除实体。取消后该行动画移出并显示可撤销 Snackbar；撤销失败则恢复并提示。
- 关联 id 对应实体明确不存在时显示 `关联内容不存在`，提供「移除失效关联」；查询失败显示 `关联暂时无法加载` + `重试`，不得把加载失败当作已删除，也不得跳转空白编辑器。

### 7.6 新建、类型覆盖与子项表单（U-01 / U-09）

**新建入口保持单一 FAB**。点击后沿用 FAB 到表单的 sharedBounds morph，但两个旧表单整合为一个 `EntityEditorSheet` 状态模型，不在后台各创建一份草稿。

- 顶部为「任务 / 笔记」双段选择器，默认 kind 由清单语境给出；任务型清单与全部智能清单默认任务，笔记型清单默认笔记。选择器高 40dp，选中项使用 `secondaryContainer`，图标与文字同时变化，不只换色。
- 标题随 kind 显示「新建任务 / 新建笔记」，输入提示分别为「要做点什么？」与「想记点什么？」；创建按钮为「添加任务 / 添加笔记」。空标题禁用创建，空白字符不视作有效标题。
- 任务态展示描述、优先级、预计时长、提醒、重复、附件；笔记态展示标题与 Markdown 正文、附件入口，不展示勾选状态或优先级。
- 类型切换保留标题、描述/正文、附件及已编辑内容；只在 task→note 时隐藏任务字段，再切回 task 恢复，绝不静默清空。笔记成功创建后打开编辑器；任务创建后回到列表并插入对应位置。
- 创建过程关闭草稿时，若已有输入则提示 `放弃未保存的内容？`，操作「继续编辑 / 放弃」；未输入直接关闭。系统返回与 scrim 使用同一确认规则。

**子项创建表单**：沿用现有 DETAIL → ADD_SUBTASK 面板，只保留类型选择（默认 task）、标题、优先级（task 时）与取消/添加按钮。V1 **完全移除分组选择**，不显示禁用态；副文案明确 `添加到「父项标题」 · 跟随父项所在清单和分组`。写入时由后端继承根实体 category/group，前端不允许覆盖。键盘 Done 等同添加，输入法不遮挡按钮。

### 7.7 长按操作菜单、删除与手势仲裁（U-08）

采用现有 `NionBottomSheet` 的模态底部抽屉，而不是贴近手指的小上下文菜单：手机上更容易触达，且可自然扩展清单/分组选择。标题为实体名与 `任务` / `笔记` 类型说明，首版操作顺序如下：

1. `移动到清单`：二级单选列表，显示当前清单；智能清单作为来源视图时可移到真实清单，但不能以智能清单为目标。
2. `更改分组`：仅在已选真实清单后出现，含「未分组」；移动清单与分组一次提交，目标清单无对应分组时重置为未分组。
3. `转为笔记` 或 `转为任务`：根据实体 kind 只显示反向项，文案下附保留说明；对子项同样可用。
4. `选择多项`：进入既有多选模式，不让用户以为原有能力消失。
5. `删除`：独立弱分隔后的 error 文本项，不使用红色实心按钮吸引注意。

**与拖拽的冲突处理是实施前置条件**：当前 `SharedTaskList` 的长按既用于拖动也在原地松手后进入多选。定稿为「长按后拖动 = 排序；长按原地松手 = 打开此实体操作菜单；菜单中的『选择多项』才进入多选」。拖动阈值之前不显示菜单；一旦越过阈值，取消菜单与点击。选择模式下短按切换选择，不打开详情。此变化需在 B4 验收中专门复测父子组拖拽，不能简单叠加 `combinedClickable`。

**删除保护**

- 选择删除后先收起菜单，再显示 AlertDialog。标题按 kind 为 `删除任务？` / `删除笔记？`；正文包含实体名与保留策略：`只删除当前项，3 个子项将上移一级。此操作无法撤销。`；无子项不显示数量。本次采用**子项保留**而不是级联删除：直接子项改挂到被删实体的 parent（可为 null），更深层级保持不变，B4 需为此提供原子 core 操作并清理另一端残留的 linked_task_ids。现有 `delete_task` 只删当前实体、会让子项 parent 悬空（`nion_core.rs:553-575`），因此不得在未补齐该语义前沿用旧接口冒充完成。
- 默认焦点为「取消」；「删除」使用 error 色文本按钮，不需输入名称。执行中禁用两个按钮，成功后才关闭并移除列表；失败保留详情与实体、显示 `删除失败，请重试`。
- 移动、转换、分组更改用乐观 UI + 原值快照回滚；失败 Snackbar 明示 `未保存：原因` 和「重试」。转换不弹确认，因为不是删除且可再次转换；task→note 辅助说明 `再次转为任务时可恢复完成状态`，note→task 为 `将作为待办任务显示，内容与关联保留`。
- 笔记编辑器顶部的关联任务 chip：短按只负责打开任务详情；右侧独立 X（48dp 点击区）解除关联，不再点击 chip 即删除。打开任务详情后，编辑器返回键回到原笔记与原编辑/预览状态。解除关联也按 7.5 的撤销规则处理。

### 7.8 笔记编辑器与跨页连续性

- 将 `NotebookEditor.kt` 的 60% 状态栏折减替换为完整 `statusBarsPadding`；返回与编辑/预览按钮保留至少 48dp 点击区，不能用缩小 Box 换取紧凑视觉。
- 顶栏为返回、可编辑标题、编辑/预览切换；关联栏在标题下独立一行。关联多时可横向滚动或进入完整选择器，不挤压标题与返回键。
- 编辑器保留 note.id 对应的标题、正文、previewMode、滚动位置。跳转关联任务再返回时，不能自动重置成编辑态或丢失未保存草稿；文本持久化失败须显示状态，不能用「自动保存」假装成功。
- 实体跳转统一由导航请求承载：`openEntity(entityId, source)`。它只描述目标与来源，不在 Composable 内叠加多个独立 `expandedTaskId`。来源至少包括任务列表、任务详情、笔记编辑器、日程、通知、聊天排期卡。
- 从伙伴面板跳转到主内容时，先记录会话与列表位置，再收起右侧面板并切换路由。系统返回优先关闭详情/编辑器，再恢复此前路由和面板状态；避免主内容与侧栏同时争抢返回事件。

### 7.9 预计时长与「预期 vs 实际」专注展示（B6）

- 新建任务与 DETAIL 的提醒行下增加 `预计时长`，默认 `未设置`，点击打开 `NionBottomSheet`。提供 15 / 25 / 45 / 60 / 90 分钟快捷选项与自定义正整数分钟，允许「清除」；非法值、0、负数禁止保存。`expected_minutes` 是预计总工作量，不是强制计时长度，也不产生结束时间字段。
- 有 reminder 且有预计时长时，卡片与详情显示 `14:00 开始 · 预计 45 分钟`；只有预计时长无 reminder 时显示 `预计 45 分钟`，不伪装成已安排。日程中的时间占用由起点 + 时长派生，UI 不新增第二套日历事件模型。
- 详情专注行：有预期时显示 `已专注 35 分钟 / 预计 45 分钟` 和 4dp 线性进度，未设置时保持现有 `专注时间 35 分钟` + 播放入口。进度超过 100% 时进度条填满，附 `已超出预计 10 分钟`，不使用 error 红，避免把投入更多时间表现为失败。
- 开始专注的预选时长默认取 `min(剩余预计分钟, 60)`，剩余不足 1 分钟或无预期时沿用现有 25 / 45 / 60 选择；用户仍可修改，不因自动选择而直接开始。
- 专注统计的任务分布行显示 `实际 / 预计`，无预期为 `实际 / 未设置`；顶部总览保持「总专注 + 次数」，不增加相互竞争的 KPI。图表用一条实际进度和文字表达，不造多色仪表盘。

### 7.10 AI 排期卡片：建议、核对、应用（U-02）

排期结果以右侧伙伴聊天流内的**结构化卡片**展示，卡片宽度填满 320dp 面板减去两侧 16dp 内边距，不使用宽表格或横向滚动。普通文本仍使用气泡，排期卡为独立 surface，不放在 AI 气泡里；复用既有工具状态行表达「正在安排…」，卡片只在成功拿到完整结构化结果后出现。

**折叠态（默认）**

- 标题 `排期建议`，副标题 `已安排 7 项 · 1 项待处理`，右上角 `预览` 标签；不显示「成功」直到真实写入。
- 摘要展示 `预计最早完成：10 月 28 日`，无 assignments 时不伪造日期；底部一行 `确认后才会修改任务时间`。
- 默认展开第一天，最多显示 3 条分配项；每条为 `09:00–10:30`（`labelMedium`，等宽数字）+ 任务名 + `90 分钟`。跨天按日期分为小标题 `今天 · 10月25日` / `明天 · 10月26日` / `10月27日 周二`。
- 其余分配折叠为 `查看全部 7 项安排`，未排入单独显示 `1 项未排入`。点击整条分配跳详情；点击日期行的 ChevronRight 或卡片次按钮「查看日程」跳对应日程日期（默认第一天），日期文字与整行不绑定另一个动作。

**展开态与未排入**

- 展开在当前消息内完成，使用 `AnimatedVisibility` 高度 + 淡入，限制可视高度并由聊天 LazyColumn 负责滚动，不在卡片里再造难滚动的嵌套长列表。超过 20 条时进入全屏/大浮层只读预览，按日懒加载。
- 未排入区采用无红色的 `surfaceContainerHigh` 信息块：`任务名 — 未设置预计时长`，操作 `去补充`，打开该任务详情并聚焦预计时长。其他原因如实显示 `90 天内没有足够时间窗`，不得一律写成「时间不足」。
- 无可用时间窗时给出去 7.11 设置的入口；零 assignments 时主按钮为 `调整时间窗`，不显示可应用的假成功按钮。

**确认状态机**

| 状态 | 卡片文案与操作 | 数据语义 |
|---|---|---|
| preview | 主按钮 `应用排期`，次按钮 `查看日程` | 尚未修改任何任务 |
| confirming | 按钮内进度 `正在应用…`，禁止重复点击；保留结果可见 | 正在逐项写入，可收起侧栏 |
| applied | `已更新 7 项安排`；只读 + `查看日程` | 所有目标写入成功；旧卡不能再次应用 |
| partial | `已更新 5 项，2 项未更新`，逐项显示原因；`重试未成功项` | 明确部分成功，不整体标成功或全量重试 |
| failed | `未能应用排期，任务时间未修改`；`重试` | 确认请求失败且没有写入；有写入必须归 partial |
| stale | `部分任务时间已变化，请重新排期`；`让伙伴重新排期` | 不覆盖预览之后的人工修改 |

确认操作直接由本地 UI 发起 `schedule(confirm=true)`，与 AI 新一轮文本解耦。应用完成更新对应任务、日程、列表计数，以 200ms 局部高亮提示变化，不清空聊天或强制切页。查看日程是用户主动行为，不因应用成功自动打断聊天。

### 7.11 每日时间窗设置（U-03）

在设置页新增「任务与日程」区，置于「主题颜色」之后、「我的位置」之前；包含 `智能清单`、`每日时间窗` 两个入口卡，避免把新增控件继续堆进权限区。`每日时间窗`折叠态副标题显示 `09:00–11:00、14:00–17:00、20:00–24:00 · 每天`，无设置为 `未设置，AI 排期前需要补充`。

点击使用 `NionBottomSheet` 打开编辑表单，标题 `每日时间窗`，说明 `每天都使用这些时段，排期不会占用时段外的时间`。V1 不提供按星期选择，不引入更多设置层级。

- 每行：开始时间、结束时间、删除；下方 `+ 添加时段`。点击时间调起 Material 3 TimePicker，24 小时制；默认新增时段取最后一个时段结束后 1 小时，无时段时默认 09:00–10:00。
- `24:00` 仅允许作为结束值，表示当天结束，不作为开始值；普通时间范围 00:00～23:59。V1 不允许跨午夜区间（22:00–02:00），需用户拆成当天与次日两段；跨天不拆任务时长。
- 本地草稿支持编辑/添加/删除，只有点击 `保存` 才序列化 `daily_time_windows`。保存前校验：开始早于结束、任意两区间不重叠、按开始时间排序；行内错误分别显示 `结束时间需晚于开始时间` / `此时段与 09:00–11:00 重叠`，定位到对应行。
- 空数组合法，表示未配置而非全天可用。无有效时段时 AI 返回 unplaced/原因，不能默认为 00:00–24:00。保存后折叠态即时更新，排期工具下一次预览读取新值，不改写已生成/已应用的卡片。
- 有未保存修改时关闭需确认；保存失败保留草稿和已打开表单。设置保存期间只禁用保存按钮，仍可阅读已有内容。

### 7.12 智能清单：侧栏与设置（U-04）

**侧栏保持扁平，不做多层可折叠树。** 原「清单」标题保留，下面是固定顺序的智能清单，再以弱分隔与 `我的清单` 小标题区隔自建清单。智能清单永不进入拖拽排序、不显示删除 X，右键/长按也不出现重命名或删除。

- 固定顺序：今天、明天、本周、最近 7 天、最近 30 天、收集箱；默认只启用今天、收集箱，因此升级前默认视图不发生变化。
- 图标优先复用 `CalendarClock`（今天/最近 7 天）、`Calendar`（明天）、`CalendarDays`（本周）、`CalendarClock`（最近 30 天）、`Inbox`（收集箱）；缺少的图标统一补进 `LucideIcons.kt`，不在页面内自绘多套风格。同色系中性图标，不给六项分配彩虹色。
- 启用的新项按注册表顺序直接插入，采用 `animateItem` 位移 + 180ms 淡入，选中的当前项不移动；隐藏当前所在智能清单时先回退到今天，再移除，并提示原因。
- 每项只显示名称与右侧数字徽标，数值为未完成 task 数；note 不进入待办计数，但仍在打开该清单后的列表和顶部统计中显示。自建清单仍保留拖拽排序、新建和删除。侧栏底部 `管理智能清单` 文字入口直达设置对应卡片，不挤入新建清单按钮。

**设置项**：`任务与日程 → 智能清单` 的卡片默认折叠，摘要为 `已启用 2 项`。展开后六项各一行，含名称、时间口径与启停控件；可编辑项使用 Switch，语义是「在侧栏显示」，不是删除数据或停用提醒。

| 名称 | 设置说明（按 5 的定稿口径） |
|---|---|
| 今天 | 提醒日期是今天 |
| 明天 | 提醒日期是明天 |
| 本周 | 本周一至周日，含今天 |
| 最近 7 天 | 今天及此前 6 天 |
| 最近 30 天 | 今天及此前 29 天 |
| 收集箱 | 尚未归入清单的内容 |

今天与收集箱固定启用并锁定，其他四项可自由启停，避免出现空侧栏或「操作后报错」的假开关；锁定项显示 `默认` 与锁图标，不提供 Switch。隐藏当前所在的非默认智能清单时先回退到今天，再移除并显示 `已切换到今天`。智能清单设置变更只影响聚合入口，不修改真实清单和实体归属。

### 7.13 通知与高优提醒全屏页（U-05）

**展示原则：系统通知始终存在，浮窗只是可选增强。** 显示浮窗不撤通知；只有用户点击通知/浮窗的「知道了」「稍后提醒」「今天算了」「开始专注」等明确处理动作，或打开提醒详情并确认处理后，才按既有动作语义取消通知。当前 `ReminderWorker` 两处 dismiss 与 `ReminderOverlay` 事件到达时的 dismiss 均在本次修复范围，不能只修 Worker 留 UI 漏洞。

**通知内容**：标题为任务名，收拢正文首次为 `该做啦 · 现在`，重复提醒为 `第 N 次提醒`，展开正文为清理 Markdown 后的伙伴文案。高优任务沿用 HIGH channel 与声音/震动，附加 `CATEGORY_REMINDER`、`VISIBILITY_PRIVATE` 和 full-screen intent；普通任务不申请全屏打断。通知只显示任务标题和动作，不显示笔记正文或聊天隐私；锁屏是否展示详情遵循用户系统设置。

- **fullScreenIntent 页面**：独立轻量 `ReminderFullscreenActivity` 或等价全屏宿主，不使用聊天页代替。背景 `colorScheme.background`，顶部 `Nion · 任务提醒` 与闹钟图标，中间任务名最多 3 行、预计时长（若有）、伙伴文案最多 6 行；底部固定主按钮 `开始专注`、次按钮 `稍后 5 分钟`、文字按钮 `今天算了`。通知与全屏页共用动作标签、顺序和语义，不在两个入口分别发明一套按钮。
- 高优但无需专注的任务，主按钮改为现有「知道了」语义；按钮是否完成任务必须与 `ReminderCompleteHelper` 的真实行为一致，不能仅关闭界面却暗示已完成。
- 页面出现时屏幕唤醒与锁屏上展示遵循 Android 版本能力；禁止用循环动画、闪烁或强制持续振动制造紧迫感。仅首次提示一次触感/声音，后续交给系统通知。
- 从全屏页进入专注或详情时清理对应提醒 UI，系统返回/手势关闭只代表暂时关闭全屏页，**保留系统通知**，让通知继续承担兜底。系统不授予全屏能力、设备不支持或厂商限制时退化为 HIGH 通知 + heads-up，不阻断提醒 Worker。
- 点击通知主体改为打开该任务详情（而非无条件展开伙伴面板）；通知的 Action 保持现有开始/稍后/忽略语义。冷启动与 `onNewIntent` 都走同一 `openEntity` 请求，pending action 需以可观察状态承载并在消费后清除，防止热启动收不到新 Intent 或回退时重复跳转。

### 7.14 后台提醒与厂商设置引导（U-06）

不新增首次启动强制引导页，不连续索要权限。复用设置页「权限设置」中的 `后台提醒` 卡片，在它下面按需展开 `厂商后台运行` 区块；只在支持厂商且标准电池优化未设置，或用户已设置提醒但检测到厂商限制入口时出现。

- 卡片状态分 `已设置` / `建议检查` / `未设置`，不承诺可读取所有厂商内部开关。标准 Android 状态可验证时写确定结果，厂商层只能写 `请在系统设置中确认`，不可伪造「已修复」。
- 点击展开 `NionBottomSheet`，标题 `让提醒准时到达`，三条简短步骤：`允许后台运行`、`允许自启动`、`将省电策略设为不限制`。根据 `Build.MANUFACTURER` 只展示当前厂商的名称与说明，不展示无关品牌清单。
- 主按钮 `打开系统设置` 走既有 `VendorBatteryHelper.openBatterySettings`，次按钮 `我知道了`。每次从系统页返回在 ON_RESUME 重查标准权限；厂商设置项保留 `我已检查` 的本地勾选，与系统实测状态分开展示。
- 提供 `检测提醒` 只在用户主动点击时创建一个 1 分钟后的本地测试提醒，并明确说明将产生一条系统通知；不得在打开设置页时自动创建。测试结果只能报告「已收到/未收到」，未收到时给回系统设置入口。
- 通知权限被拒绝时优先修复通知权限：卡片说明 `系统通知已关闭，悬浮窗不能作为可靠替代`，按钮直达应用通知设置。悬浮窗未授权只影响增强展示，不显示为阻断性 error。高优全屏提醒另需检查 `NotificationManager.canUseFullScreenIntent()`（支持的 API 级别），未获系统允许时提供系统设置入口；标准通知权限、悬浮窗权限、全屏提醒能力是三种独立状态，不互相冒充。

### 7.15 动效语言、返回栈与减少动画

动效目标是维持空间连续性，不是让每个状态都弹跳。所有新增动画集中在主题/动效常量中管理；相同场景不另创时长和 easing。沿用 `FastOutSlowInEasing` 与既有 spring，业务操作无需等待动画结束才写库。

| 场景 | 规格 | 约束 |
|---|---|---|
| 卡片 ↔ 详情 / 笔记编辑器 | 沿用 sharedElement，spring(dampingRatio=0.8f, stiffness=MediumLow) | 两端同 shape/背景，内容不同时刻不重影；返回缩回原卡片 |
| FAB ↔ 新建表单 | sharedBounds，容器形变 + 内容短淡入 | 标题和输入框首帧位置稳定，键盘不叠加位移动画 |
| 面板内前进/返回 | 180～240ms，水平位移不超过宽度 1/4 + fade | 子项详情用栈返回，不重建外层 scrim |
| 展开/折叠 | 180～220ms expand/shrink + fade | 大列表不 `animateContentSize` 到无限高；采用固定视窗/懒加载 |
| 选中、设置开关、类型转换 | 160～200ms 颜色/图标 crossfade | 颜色过渡不以 `Color.Transparent` 为目标 |
| 列表新增/移动/删除 | 复用 `animateItem`，稳定 id + contentType | 增量更新，不全表 clear/re-add；拖拽期间禁播位置动画 |
| 排期卡片应用 | 200ms 状态文字淡变 + 成功项局部底色 | 不做彩带、不做成功全屏弹窗 |
| 全屏提醒 | 180ms 淡入，退出 150ms | 不循环、不闪烁、不强制 spring 过冲 |

- 返回优先级：系统模态/编辑子面板 → 实体详情返回栈 → 笔记/任务详情本身 → 由聊天/通知打开详情的来源侧栏与路由 → 左/右侧栏 → 当前路由。普通从列表打开详情的场景，关闭详情后不因侧栏曾打开过而重新弹出。任一侧栏与主内容的 BackHandler 只能有一个生效。
- 用户主动上滑阅读聊天时，排期卡更新、工具状态追加不得抢滚动位置；关闭再打开伙伴恢复同一会话、卡片展开状态和位置。
- 检测系统「移除动画/减少动画」或 animator duration scale=0 时，禁用共享元素位移、弹簧过冲和装饰性进度动画，保留不超过 100ms 的必要状态淡变或立即切换。新交互的逻辑完成不得依赖动画回调；现有任务完成的「先动画后写库」保留为视觉效果，但须将挂起写库改为可取消协程/超时兜底，实体离屏、减少动画或动画被取消时立即完成原写库，不允许永久停留在视觉完成态。
- 触感只在长按进入菜单/拖拽、排期确认成功、任务完成时给轻反馈；普通切换、键盘输入与列表滚动不振动。系统关闭触感时遵循系统设置。

### 7.16 状态、可访问性与流畅度验收

**状态完整性**：每个新增异步区块都区分首次加载、有内容刷新、空、错误、部分成功。写入中保留当前内容与按钮防重，写失败不清草稿。不得用「没有数据」代替加载失败，也不得在切换清单时把上一个清单内容当新内容闪现。

**可访问性**

- 图标按钮有具体描述，如 `取消关联「任务名」`，而非统一的 `删除`；任务勾选朗读 `完成任务，标题` / `标记为未完成，标题`，笔记图标不伪装成可点击 checkbox。
- 时间区间完整朗读为 `今天 9 点到 11 点，任务名，预计 120 分钟`；图表同时提供数值文字。颜色、细树线、删除线都不是唯一状态信号。
- 动态字号下允许标题与摘要换行，排期日期与操作按钮可换行，不截断保存/删除主操作；窄屏与 1.3 倍字体下仍可无横向滚动完成主要任务。
- Snackbar 与状态变化提供语义通知；弹窗打开时焦点到标题，关闭后回到触发控件。所有触摸目标至少 48dp，不能用视觉尺寸 24dp 直接充当命中区域。

**Compose 性能约束**

- 列表项、section header、spacer 都使用稳定 key 与 contentType；`kind` 可并入 contentType，实体转换时允许内容替换但不能使用列表 index 作为 key。
- kind 分布统计、智能清单过滤、子孙树构建放进 ViewModel / `derivedStateOf` / `remember(source)`，不在 LazyColumn item 中递归全表查找或读 SQLite。
- 预览/确认状态进入 ViewModel 并可随会话持久化，侧栏移出组合不丢任务；数据库操作继续在 `Dispatchers.IO`。动画只读 state，不在 draw/layout 阶段触发写入。
- 拖动偏移使用 `graphicsLayer` / offset lambda 延迟读取；排期卡展开、详情滚动、拖拽排序不触发整个 NavHost 重组。沿用 `docs/compose-animation-best-practices.md` 的颜色、增量 diff 与 sharedElement 约束。
- 详情层级很深、关联笔记很多时默认折叠和懒加载；单帧不做全量 Markdown 解析或数十个日程卡片重复排版。

## 9. 验收标准（逐批次）

- **B1**：反馈报告 P2/P3/P4 三场景复测——update(ids, parent) 返回 success 且与数据一致；仅 parent 变更不再报错；query(note) 无 name 可枚举、精确名搜索子笔记可见。全工具链「报错但已写入」为零。
- **B2**：息屏状态下到达提醒时间的任务产生系统通知（高优全屏唤亮）；亮屏行为不回退。Worker、App 内浮窗、后台浮窗任一路径展示后通知仍在；全屏权限被拒绝时 HIGH 通知仍可达；冷/热启动通知点击都只打开一次目标详情。
- **B3**：同一笔记本内同时存在可勾选任务与不可勾选笔记；双向互转状态正确（完成态保留/重置规则）；任务清单内可建笔记；新建切换不丢草稿；纯任务、纯笔记、混合、智能清单的统计/空态逐行符合 7.4。
- **B4**：任务详情可见子孙树并可跳转；关联笔记双向可见可跳转；返回恢复父级和原滚动位置；长按拖动仍完成父子组排序，原地松手只弹操作菜单；移动/分组/互转/删除可用；删除后子项按 7.7 上移且没有失效关联。
- **B5**：设置启用「本周」后侧栏出现并正确聚合；默认视图与现状无差异；今天/收集箱不可关闭，其他项关闭不修改实体；周日/周一与本地时区边界、含今天的最近 N 天口径有自动化测试。
- **B6**：用户排期案例可解——定海神针卷（一次性 150 分钟）+ 行测判断推理系列课（59/40/90/37/60/79/93 分钟序列）+ 每日三时间窗（09-11/14-17/20-24）+ 每日 60 分钟碎片刷题，输出各任务时间安排与最早完成日期；expected_minutes 缺失的任务如实进 unplaced。未确认不写库；确认中途退出恢复正确；部分成功只重试失败项；预览后人工改时间的任务不被旧建议覆盖。
- **通用前端**：覆盖 7.17 的窄屏/大字体/主题/导航/权限矩阵；无横向溢出、主操作不被 IME 遮挡、空白与失败可区分、返回不丢编辑状态。连续打开关闭详情 20 次、切换类型与清单 20 次、滚动包含排期卡的聊天列表，均无重复实体、动画闪烁或显著掉帧。
- **通用工程**：每批次完成后 `cargo test -p nion-core` + `assembleDebug` 通过；涉及 core 变更的批次重新生成 UniFFI 绑定并部署验证。每次提交只包含本批次文件，不夹带其他工作区改动。

## 10. 风险与边界

- **UniFFI 约束**：嵌套 Option 不支持，3.3 已用标志位规避；Record 字段变更要求 Kotlin 侧与 `.so` 严格同版本部署（老 APK + 新 so 或反之会崩溃），每批次部署走完整 `build-android.sh` + `deploy.sh`。当前 `map_task_row` 按固定列序构造 TaskData，新增 kind / expected_minutes 时必须同步更新 SELECT 列清单与映射索引，不能只改 Record。
- **测试期迁移**：3.1 的一次性存量刷写在正式发布前必须移除并冻结语义（当前无真实用户数据，风险窗口可控）。
- **贪心排期边界**：不处理复杂约束（依赖关系、场地、人员）；跨天任务不拆分；结果定位是「建议」，最终由用户 confirm。前端不能让模型重述卡片代替稳定 proposalId 与本地确认。
- **手势与导航回归**：长按菜单会改变原「松手进多选」行为，必须在 B4 的发布说明中明示，并保留菜单内的多选入口；跨实体返回栈要防止多个 ViewModel/Route 各自消费返回事件。
- **通知厂商差异**：国产 ROM 电池白名单可能导致 AlarmManager 仍被杀，复用 VendorBatteryHelper 并对照 SymNex 实现补 7.14 引导；标准权限实测状态与「用户已检查厂商设置」分开表达。Android 14+ 的 fullScreenIntent 需声明权限、检查能力并提供降级；B2 包含 `USE_FULL_SCREEN_INTENT` 声明、全屏 Activity 的锁屏展示与唤醒屏幕配置，不得承诺所有 ROM 都能全屏唤亮。
- **删除与关联完整性**：本次选择保留子项而不是级联删除；必须在 core 事务内更新直接子项 parent 并清理双向关联，不能只改列表 UI。原删除接口语义不完整，是 B4 前置工作而非文案问题。
- **prompt 效果不确定**：4.4 记忆规则上线后需观察记录频率，过阈值（每轮都在记）则收紧措辞。
